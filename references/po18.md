# PO18（po18.tw / 脸红心跳）抓取指南

PO18 是台湾原创言情站，大陆访问需代理，全站内容需登录后可见。本文档沉淀了实战验证的完整抓取方案，正式脚本见 `scripts/po18_fetch.mjs`。

## 站点特性

| 特性 | 结论 |
|------|------|
| 网络 | 大陆需翻墙；Chrome 走系统代理，**Node 原生 fetch 不走系统代理**（直连会 `fetch failed`），所以优先用浏览器方案 |
| 防护 | 无 Cloudflare；SSR 渲染；有会话级防爬 token（`_paabbcc`） |
| 登录 | 未登录看不到任何正文（连目录的"免費閱讀"按钮都没有） |
| 付费 | 免费章可直接读；付费章必须先用账户珍珠购买，脚本只能抓"免费 + 已购"章节 |

## 核心机制：articlescontent 正文接口（重要）

正文有专用纯文本接口，比解析渲染页更稳更快：

```
章节页:  https://www.po18.tw/books/{bid}/articles/{pid}
正文接口: https://www.po18.tw/books/{bid}/articlescontent/{pid}
```

**三条铁律（踩过的坑）：**

1. **Referer 必须是对应章节自身的 `/articles/{pid}` 页面**。Referer 不匹配（如首页、其他章节、articlescontent 自身）时接口不报错，而是返回一个 **GTM JS 壳页**（内容以 `window.dataLayer = ...` 开头，长度足够大、状态 200），极易误判为抓取成功。校验：解析后任一段落含 `dataLayer` / `function(` 即为壳页，需重试。
2. **浏览器内 `fetch` 无法伪造 Referer**（浏览器安全策略静默忽略自定义 Referer）。所以纯靠页面内 fetch 必须每章先 `page.goto(章节页)` 再 fetch 接口；或者纯 HTTP 请求时每章显式设 `Referer: 对应章节页URL`（Node fetch 不走系统代理，纯 HTTP 方案仅在用户直连可达或有代理环境变量时可用）。
3. **返回的 HTML 是非标准的**：`<p>` 标签不闭合（`<p>段落` 后直接跟下一个 `<p>` 或 `<blockquote>`），标准解析器会把整章当一个段落。按"标签→分隔符"方式处理，不要用 DOM 语义解析。

**返回结构：**

```html
<h1>章节标题</h1><p>第一段…<blockquote cite='...' class='copyright' style='...'>vY7q2fZk…</blockquote><p>&nbsp; 第二段…
```

- `<h1>` = 章节标题
- `<p>` 不闭合，每个 `<p>` 开启一个新段落
- 每段之间穿插 `<blockquote class='copyright'>40位随机串</blockquote>` 防爬水印，**整块删除**

**解析算法**（已在 `scripts/po18_fetch.mjs` 验证）：

```js
html.replace(/<blockquote[^>]*>[\s\S]*?<\/blockquote>/gi, '')  // 水印
    .replace(/<h1[^>]*>[\s\S]*?<\/h1>/i, '')                   // 标题单独取
    .replace(/<p[^>]*>/gi, '\n')                               // p → 段落分隔
    .replace(/<[^>]+>/g, '');                                  // 剩余标签剥掉
// 再逐行: &nbsp;→空格、\u3000\u00a0→空格、trim、滤空行
```

## 认证（三选一）

| 方式 | 适用人群 | 做法 |
|------|---------|------|
| ① cookie 导出（推荐） | 会用 DevTools | Chrome 登录 PO18 → DevTools → Application → Cookies → 复制全部，存 JSON 数组，`--cookies po18_cookies.json` 注入 |
| ② storageState | 不会导 cookie | 脚本 `--save-state` 打开有头浏览器手动登录一次，保存 `po18_state.json`，之后复用 |
| ③ 账密 POST | 不推荐 | `POST https://members.po18.tw/apps/login.php`，data: `account/pwd/remember_me=1/comefrom_id=2/owner=COC/client_ip/url`。需本机 IP，易触发风控，仅作了解 |

**cookie 关键字段**（缺一可能失败）：
- `authtoken1~6`：登录凭证（httpOnly）
- `_po18rf-tk001`：CSRF token（httpOnly + secure，注入时保留原属性）
- `_paabbcc`：会话/防爬标识，**值随登录会话变化，必须用最新导出的**；旧值失效表现为页面重定向或正文为空

**登录态判断**：页面出现 `登出` 链接 / 文本 `xxx您好!`。

## 目录解析

目录页 `https://www.po18.tw/books/{bid}/articles`（分页 `?page=N`，页数取 `.pagenum a[href*=page]` 的最大值）。

```js
title:  '.book_info>h1'
author: '.author>h2'
列表:   '#w0>div'，每项内:
  counter: '.l_counter'   // 四位编号 "0002"
  name:    '.l_chaptname'
  href:    '.l_btn>a' 的 href
```

**付费判定**：免费章按钮文本为「免費閱讀」、href 是真实路径；付费章按钮文本为「N 💰 訂購」、**href 是 `javascript:`**。判定规则：`paid = !href || /^javascript/i.test(href)`。

注意书籍真实作者 ≠ 登录账号名（作者从目录页 `.author>h2` 取，登录账号在页头「xxx您好!」）。

## 抓取流程（脚本已固化）

1. 注入凭证 → 打开目录页 → 验证登录态（无凭证则打开有头登录页）
2. 解析目录（含分页），列出章节，`--list` 可仅查看
3. 每章：`goto /articles/{pid}` → 页面内 `fetch /articlescontent/{pid}` → 解析 + 壳页检测（重试 3 次）
4. 每章落盘 `{out}/po18_{bid}_raw.json`（断点续传，重跑自动跳过已完成章节）
5. 生成 `《书名》by作者.txt`：书名 + 作者 + `第N章 标题` + 正文（段落空行分隔）

## 清洗规则（PO18 特有）

- `blockquote.copyright` 水印（接口层已整块删除）
- `&nbsp;` 与 `\u3000` 全角空格缩进 → 清理
- 目录展示的"字数"字段（`.l_font`）可用来交叉校验抓全（如正文长度 ≈ 标注字数）
- 付费章未购时跳过并在结尾列出，用户购买后重跑即可补抓（断点续传自动处理）

## 降级策略（用户无法访问 PO18 时）

PO18 大陆被墙且必须登录+购买。若用户无法翻墙或无账号：

1. 询问用户是否接受盗版源替代（内容可能缺章/有乱码/更新滞后）
2. 走 `references/search-and-compare.md` 的全网搜索流程，常见替代源为笔趣阁系镜像（无登录、无防护、SSR，抓取简单）
3. 盗版源缺最后几章时，可提示有条件的用户从正版补抓后拼接（两段式拼接见 `references/search-and-compare.md`）

## EPUB 输出（可选增强）

参考 Wenmoux/j8tool 的 `p18dtoEpub.js`：JSZip 打包 `META-INF/container.xml + mimetype + OEBPS/{toc.ncx, content.opf, Styles/main.css, Chapter/*.html, Images/}`。抓取脚本的 raw JSON（每章 paras）可直接转 `chapter_N.html`。仅在用户明确要 epub 时再做，默认输出 txt。
